# b PDF Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A fully working, accessibility-first, offline Android PDF toolkit (iLovePDF-like) released as open source.

**Architecture:** Single `app` module. `core/pdf` holds pure PDF operations on `File`s (PdfBox-Android), `core/work` runs them with progress/cancel state, `core/files` bridges SAF URIs ⇄ cache files, `core/a11y` holds TalkBack helpers, `feature/<tool>` holds one Compose screen + ViewModel per tool.

**Tech Stack:** Kotlin 2.x, Jetpack Compose Material 3, Navigation Compose, DataStore, PdfBox-Android, Android PdfRenderer, Tesseract4Android, Robolectric + Compose UI test, GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-10-21-b-pdf-design.md` (read it — §4 tool list and §5 accessibility checklist are binding).

## Global Constraints

- Package `io.github.wzehirx.bpdf`; app name "b PDF"; minSdk 26, targetSdk/compileSdk 36; JVM target 17.
- License Apache-2.0; every dependency must be Apache/MIT/BSD/OFL compatible. No Google Play Services, no network permission.
- All user-visible strings in `res/values/strings.xml` (English) and `res/values-tr/strings.xml` (Turkish). No hard-coded UI text, including contentDescriptions and announcements.
- Every screen meets spec §5 (labels, headings, custom actions instead of gesture-only, ≥48dp targets, live-region announcements, state descriptions) and has a Robolectric Compose semantics test.
- Engine code (`core/pdf`) never touches `ContentResolver`, `Context` (except `PdfBoxInit`) or UI; it takes `File`s.
- Load PDFs only through `PdfLoader.load` (temp-file memory mode + error mapping).
- Text drawn into PDFs (watermark, page numbers, signature) uses the bundled embedded Unicode font (`assets/fonts/NotoSans-Regular.ttf`, OFL) so Turkish characters render.
- Build/test commands: `./gradlew :app:testDebugUnitTest`, `./gradlew :app:lintDebug`, `./gradlew :app:assembleDebug`. A task is done only when all three pass.
- Commit after every task with Conventional Commits; push to the working branch; update `docs/PROGRESS.md` (mark task done, next task).

## Review Focus

1. Password-protected input in any tool → user is asked for the password (PasswordDialog), wrong password gives a specific message; never a crash.
2. Turkish characters (ğüşıöçİĞÜŞÖÇ) in watermark, page numbers, signature and metadata → rendered/stored correctly (embedded font, Unicode metadata).
3. Invalid page-range text (`"5-2"`, `"0"`, `"abc"`, `"1-"`, pages beyond count, empty) → localized, specific error on the field, announced; operation not started.
4. Large inputs (300+ pages, 100 MB scans) → no OOM: temp-file memory, pages streamed, bitmaps recycled, thumbnails downsampled.
5. Content URIs without a usable display name / extension, and configuration change (rotation, font scale change) mid-operation → result still saved with a sensible name; running operation survives (state in ViewModel).

Tests pinning each line: (1) Task 13 `PasswordFlowTest`, plus `PdfLoaderTest.encryptedWithoutPassword_throwsPasswordRequired`; (2) Tasks 16/17/20 `*_turkishText_roundTrips`; (3) Task 2 `PageRangesTest`; (4) Task 2 `PdfLoaderTest.usesTempFileMemory` and Task 10 `ThumbnailLoaderTest.downsamples`; (5) Task 3 `FileRepositoryTest.suggestName_*` and `OperationRunnerTest.survivesCollectorCancellation`.
